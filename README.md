# VPg01-llm-memory-bot — два Telegram AI-бота с памятью и тезисами

Серия из двух Telegram-ботов на Python 3.11, отвечающих через OpenAI-совместимый API:

| Бот | Режим | Описание |
|---|---|---|
| **bot-nomemory** | `USE_MEMORY=False` | Базовый бот без памяти: каждый запрос обрабатывается независимо (системный промпт + текущее сообщение). |
| **bot-memory** | `USE_MEMORY=True` | Бот с двухуровневой памятью: краткосрочная (история сообщений) + долгосрочная (тезисы — устойчивые факты о пользователе, автоматически выделяемые моделью). |

Оба бота собираются из одного Dockerfile и отличаются только переменной окружения `USE_MEMORY` и токеном Telegram-бота.

## Возможности

- Приём текстовых сообщений из Telegram (`python-telegram-bot` v21+, long polling).
- Запрос к LLM через OpenAI-совместимый клиент с системным промптом
  `Ты полезный AI-ассистент. Отвечай по делу.`.
- В режиме с памятью:
  - replay последних `HISTORY_LIMIT` сообщений как контекста;
  - **Structured Outputs** через Pydantic (`client.beta.chat.completions.parse`): модель
    возвращает JSON вида `{"message": ..., "theses": [...]}`; пользователю отправляется
    только `message`, а каждый тезис сохраняется в БД;
  - fallback-парсинг JSON из текста ответа, если модель/прокси не поддерживает structured output;
  - инъекция сохранённых тезисов в системный промпт («Вот факты, которые ты знаешь о пользователе…»).
- Команды: `/start`, `/help`, `/reset`, `/reset_all`, `/mytheses`.
- Меню команд бота в Telegram (кнопка «Меню») настраивается через `set_my_commands`
  (через `post_init` Application) в зависимости от режима.
- Обработка всех ошибок (сеть, API, парсинг, БД): логирование + вежливое сообщение пользователю.
- Готовая контейнеризация (Docker / docker compose) с непривилегированным пользователем.

## Команды бота

| Команда | Доступна | Действие |
|---|---|---|
| `/start` | всегда | Короткое приветствие |
| `/help` | всегда | Описание функционала (зависит от режима) |
| `/reset` | `USE_MEMORY=True` | Очищает **только историю сообщений**. Тезисы остаются. |
| `/reset_all` | `USE_MEMORY=True` | Полностью очищает историю **и все тезисы**. |
| `/mytheses` | `USE_MEMORY=True` | Показывает нумерованный список сохранённых тезисов. |

Список команд также устанавливается в меню Telegram (`set_my_commands`) при старте бота через `post_init`.

## Переменные окружения

Скопируйте `.env.example` в `.env` и заполните значения:

| Переменная | Назначение | Пример |
|---|---|---|
| `OPENAI_API_KEY` | API-ключ модели | `sk-...` |
| `OPENAI_BASE_URL` | Базовый URL OpenAI-совместимого API | `https://api.proxyapi.ru/openai/v1` |
| `OPENAI_MODEL` | Имя модели | `gpt-5.6-luna` |
| `TEMPERATURE` | Температура генерации (клампится в [0, 2]) | `1` |
| `LOG_LEVEL` | Уровень логирования | `INFO` |
| `BOT_TOKEN` | Токен Telegram-бота (для бота без памяти) | `123456:ABC-DEF...` |
| `USE_MEMORY` | Режим с памятью (True/False) | `False` |
| `BOT_TOKEN_MEMORY` | Токен для memory-версии бота | `123456:XYZ-...` |
| `DB_PATH` | Путь к файлу SQLite (memory-режим) | `bot_memory.db` |

> Реальный `.env` не коммитится. В репозитории лежит только `.env.example`.

### Про Structured Outputs

Для надёжного выделения тезисов используется механизм **Structured Outputs**
(`response_format=StructuredResponse`, Pydantic-модель `StructuredResponse`). Он требует модель, поддерживающую эту функцию
(например, `gpt-4o` / `gpt-4o-mini`). Если прокси или выбранная модель её не поддерживают,
бот автоматически переключается на обычный completion + ручной парсинг JSON из текста ответа,
поэтому работа не прерывается. Для гарантированного JSON укажите `OPENAI_MODEL` из числа
поддерживающих structured output.

## Локальный запуск

```bash
# Установка зависимостей
pip install -r requirements.txt

# Подготовка конфигурации
cp .env.example .env   # затем отредактируйте .env

# Запуск бота без памяти (по умолчанию)
python -m app.main

# Запуск бота с памятью
USE_MEMORY=True python -m app.main
```

## Запуск через Docker

Проект поднимает **два бота одновременно**:

- **bot-nomemory** — базовый бот без памяти (`USE_MEMORY=False`, токен из `BOT_TOKEN`).
- **bot-memory** — бот с краткосрочной и долгосрочной памятью (`USE_MEMORY=True`, токен из `BOT_TOKEN_MEMORY`).

```bash
# Поднять оба бота
docker compose up -d --build

# Остановить оба бота
docker compose down
```

Сервисы собираются из текущей директории, подхватывают `.env` через `env_file`,
перезапускаются при падении (`restart: unless-stopped`) и работают в изолированной bridge-сети
`telegram-bots-network`.

База данных тезисов бота `bot-memory` хранится в Docker-томе `bot-memory-data` и переживает перезапуски контейнера.

## Тестирование

### Проверка краткосрочной памяти (история сообщений)

1. Напишите боту любое сообщение.
2. Напишите второе сообщение со ссылкой на первое («Что я говорил про…»). Бот должен ответить в контексте.
3. Отправьте `/reset` — бот ответит «История диалога очищена. (Сохраненные факты о вас остались)».
4. Спросите что-то из предыдущего диалога — бот больше не вспомнит контекст.

### Проверка долгосрочной памяти (тезисы)

1. Во время общения с **bot-memory** бот автоматически выделяет устойчивые факты о вас и сохраняет их.
2. Отправьте `/mytheses` — вы увидите нумерованный список сохранённых тезисов (например, «1. Пользователь хочет поехать в Италию»).
3. Отправьте `/reset` — история сообщений очистится, но тезисы останутся.
4. Спросите что-то из предыдущего контекста — бот не вспомнит сообщения, но может использовать тезисы из системного промпта.

### Проверка полной очистки

1. Отправьте `/reset_all` — бот ответит «История диалога и все сохраненные факты полностью очищены».
2. Отправьте `/mytheses` — «У вас пока нет сохранённых тезисов.»

### Проверка меню команд

- Нажмите кнопку «Меню» (слева от поля ввода) — должны отобразиться доступные команды с описаниями.

## Технические детали

- Синхронный вызов OpenAI SDK выполняется в отдельном потоке
  (`asyncio.to_thread`), чтобы не блокировать event loop PTB.
- Все обращения к SQLite синхронные и выполняются в рабочих потоках (`asyncio.to_thread`);
  соединения короткие, журнал WAL. Схема создаётся идемпотентно (`IF NOT EXISTS`).
- Ошибки сохранения тезисов/сообщений логируются, но не мешают отправить ответ пользователю.
- Меню команд устанавливается через `post_init` — асинхронный коллбек `await application.bot.set_my_commands(...)`.
- Формат логов: `%(asctime)s - %(levelname)s - %(name)s - %(message)s`, вывод в stdout.
- Приложение завершает работу с кодом `1`, если отсутствует обязательная переменная
  или polling упал с необработанной ошибкой. Сбой `set_my_commands` не фатален (логируется).
