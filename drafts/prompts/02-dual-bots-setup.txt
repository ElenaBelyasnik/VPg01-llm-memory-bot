Обнови структуру проекта, чтобы в нем работали два Telegram-бота одновременно (один без памяти, второй — с долгосрочной памятью на SQLite). 

ВАЖНО:
1. Никаких коммитов и пушей в Git без моего прямого указания. Просто создавай/изменяй файлы.
2. Перед созданием файла напиши, что именно ты собираешься сделать. После выполнения — кратко подтверди, что файл записан.
3. Не трогай файлы, которые не просили трогать (кроме тех, что нужно изменить по задаче).
4. Код production-ready: обработка ошибок, docstrings, логирование через logging.

Сделай следующее:
1. Создай папку `app` внутри корня проекта. Перенеси туда логику бота из текущего `main.py`.
2. В `app/main.py` добавь поддержку флага `USE_MEMORY` (из .env). Если `USE_MEMORY=False`, бот работает без истории (как сейчас). Если `USE_MEMORY=True`, бот должен использовать модуль `database.py` для сохранения и загрузки контекста.
3. Создай `app/database.py` — модуль для работы с SQLite3 (через встроенный модуль `sqlite3`). Он должен:
   - Инициализировать БД при старте (создавать файл `bot_memory.db`, если его нет).
   - Создавать таблицу `messages` с полями: `id` (INTEGER PRIMARY KEY), `user_id` (INTEGER), `role` (TEXT), `content` (TEXT), `timestamp` (DATETIME).
   - Иметь методы: `save_message(user_id, role, content)`, `get_history(user_id, limit=20)`, `clear_history(user_id)`.
4. В `app/main.py` добавь команду `/reset` (доступна только если `USE_MEMORY=True`), которая вызывает `clear_history` для текущего пользователя и отвечает «История диалога очищена».
5. Обнови `docker-compose.yml`, чтобы в нем было ДВА сервиса:
   - `bot-nomemory`: пробрасывает `.env` с `USE_MEMORY=False`.
   - `bot-memory`: пробрасывает `.env` с `USE_MEMORY=True` (для этого можно создать отдельный `.env.memory` или использовать `environment` в compose).
   - Оба собираются из одного `Dockerfile`.
6. В `Dockerfile` обнови `CMD` на `["python", "-m", "app.main"]` и добавь копирование папки `app`.
7. Обнови `.env.example`: добавь `USE_MEMORY=False`.
8. Убедись, что логирование в обоих случаях выводит в stdout (Docker их подхватит).
