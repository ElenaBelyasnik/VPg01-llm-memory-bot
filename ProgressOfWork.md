## Что сделано

### Этап 01 — базовый бот без памяти

Созданы файлы в корне проекта:

- **`requirements.txt`** — python-telegram-bot[job-queue]==21.10, openai==1.78.0, python-dotenv==1.1.0.
- **`.env.example`** — OPENAI_API_KEY, OPENAI_BASE_URL (proxyapi.ru), OPENAI_MODEL=gpt-5.6-luna,
  TEMPERATURE=1, LOG_LEVEL=INFO, BOT_TOKEN.
- **`main.py`** — базовый бот без памяти:
  - `load_dotenv()`, логирование в stdout (уровень из `LOG_LEVEL`).
  - Клиент `OpenAI(api_key, base_url)` создаётся на уровне модуля (fail-fast).
  - Системный промпт: `Ты полезный AI-ассистент. Отвечай по делу.`
  - `ask_model(user_text)` — одно-ходовый запрос (system + текущее user-сообщение, истории нет).
  - Асинхронный `message_handler`: блокирующий вызов SDK обёрнут в `asyncio.to_thread`;
    все ошибки ловятся, логируются (`logger.exception`) и пользователю отправляется
    сообщение об ошибке.
  - `/start`, глобальный `error_handler`, запуск через `application.run_polling(...)`.
- **`Dockerfile`** — `python:3.11-slim`, `WORKDIR /app`, послойная установка зависимостей,
  копирование `main.py`, системный непривилегированный пользователь `appuser`,
  `CMD ["python", "main.py"]`.
- **`docker-compose.yml`** — сервис `base-bot` (build: .), `env_file: .env`,
  `restart: unless-stopped`, сеть `telegram-bots-network` (driver: bridge).

### Этап 02.1 — Долгосрочная память: тезисы

**`app/database.py`**:
- Добавлена таблица `theses (id, user_id, thesis, created_at)` с индексом по `user_id`.
- Методы: `save_thesis(user_id, thesis_text)`, `get_theses(user_id, limit=20)`, `clear_theses(user_id)`.

**`app/main.py`**:
- Pydantic-модель `StructuredResponse(BaseModel)` с полями `theses: List[str]`, `message: str`.
- `ask_model_structured()` — вызов через `client.beta.chat.completions.parse(..., response_format=StructuredResponse)`.
- Fallback: если модель/прокси не поддерживают structured output — обычный `ask_model()` + `_parse_theses_from_text()` (искать JSON в raw-тексте, markdown-блоках, первых `{...}`).
- `_build_system_prompt()` — в системный промпт инъектируются сохранённые тезисы пользователя (`"Вот факты, которые ты знаешь о пользователе: ..."`).
- `message_handler` — после получения ответа отправляется только `message`; каждый тезис сохраняется через `save_thesis` и логируется.
- `/reset` — очищает и историю, и тезисы (до этапа 02.3).

**`requirements.txt`** — добавлен `pydantic>=2.0.0`.

**`.env.example`** — добавлен комментарий про поддержку Structured Outputs.

### Этап 02.2 — Команда `/mytheses`

**`app/main.py`**:
- Асинхронный обработчик `mytheses_handler`:
  - Запрашивает тезисы через `db.get_theses(user_id)`.
  - Если пусто — «У вас пока нет сохранённых тезисов.»
  - Если есть — «📝 Ваши сохранённые тезисы (N шт.):» + нумерованный список.
- Регистрация: `application.add_handler(CommandHandler("mytheses", mytheses_handler))` в блоке `if USE_MEMORY`.

### Этап 02.3 — Разделение очистки: `/reset` и `/reset_all`

**`app/main.py`**:
- `reset_handler` — теперь очищает **только** историю сообщений. Ответ: «История диалога очищена. (Сохраненные факты о вас остались)».
- Новый обработчик `reset_all_handler` — очищает **и** историю, **и** тезисы. Ответ: «История диалога и все сохраненные факты полностью очищены».
- Оба зарегистрированы в `main()` в блоке `if USE_MEMORY`.

### Этап 02.4 — Меню команд и `/help`

**`app/main.py`**:
- Импорт `BotCommand` из `telegram`.
- Обработчик `help_handler` — текст зависит от `USE_MEMORY`:
  - С памятью: объясняет краткосрочную/долгосрочную память + команды.
  - Без памяти: объясняет однократные ответы без сохранения истории.
- `set_my_commands()` в `main()` перед `run_polling`:
  - Без памяти: `/start` — Приветствие, `/help` — Описание функционала.
  - С памятью: `/start` — Приветствие, `/help` — Описание функционала, `/reset` — Очищает только историю сообщений (краткосрочную память). Тезисы остаются., `/reset_all` — Полностью очищает историю и все сохранённые факты (тезисы)., `/mytheses` — Показать сохранённые тезисы (факты) о вас.
- Вызов обёрнут в `try/except` с `logger.exception` — не фатален.

### Ключевые решения
- Синхронный OpenAI SDK вынесен в поток (`asyncio.to_thread`), чтобы не блокировать event loop PTB.
- `TEMPERATURE` парсится с фолбэком на `1.0` и клампится в диапазон [0, 2].
- Отсутствие обязательных env или падение polling → выход с кодом `1`.
- Structured Outputs → fallback на ручной JSON-парсинг из текста.
- Ошибки сохранения тезисов/сообщений логируются, но не мешают отправить ответ.
- `set_my_commands` обёрнут в try/except — при ошибке API Telegram бот продолжает работу.
