## Что сделано на этапе 01

Созданы файлы в корне проекта:

- **`requirements.txt`** — python-telegram-bot[job-queue]==21.10, openai==1.78.0, python-dotenv==1.1.0.
- **`.env.example`** — OPENAI_API_KEY, OPENAI_BASE_URL (proxyapi.ru), OPENAI_MODEL=gpt-5.6-luna,
  TEMPERATURE=1, LOG_LEVEL=INFO, BOT_TOKEN.
- **`main.py`** — базовый бот без памяти:
  - `load_dotenv()`, логирование в stdout (уровень из `LOG_LEVEL`).
  - Клиент `OpenAI(api_key, base_url)` создаётся на уровне модуля (fail-fast).
  - Системный промпт: `Ты полезный AI-ассистент. Отвечай по делу.`
  - `ask_model(user_text)` — одно-ходовый запрос (system + текущее user-сообщение, истории нет).
  - Асинхронный `message_handler`: блокирующий вызов SDK обёрнут в `asyncio.to_thread`;
    все ошибки ловятся, логируются (`logger.exception`) и пользователю отправляется
    сообщение об ошибке.
  - `/start`, глобальный `error_handler`, запуск через `application.run_polling(...)`.
- **`Dockerfile`** — `python:3.11-slim`, `WORKDIR /app`, послойная установка зависимостей,
  копирование `main.py`, системный непривилегированный пользователь `appuser`,
  `CMD ["python", "main.py"]`.
- **`docker-compose.yml`** — сервис `base-bot` (build: .), `env_file: .env`,
  `restart: unless-stopped`, сеть `telegram-bots-network` (driver: bridge).

### Ключевые решения
- Синхронный OpenAI SDK вынесен в поток (`asyncio.to_thread`), чтобы не блокировать event loop PTB.
- `TEMPERATURE` парсится с фолбэком на `1.0` и клампится в диапазон [0, 2].
- Отсутствие обязательных env или падение polling → выход с кодом `1`.
